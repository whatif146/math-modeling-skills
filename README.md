# 数模技能包（math-modeling-skills）

打包日期：2026-10-29

## 一、包里有什么

| 目录 | 是什么 | 行数 / 规模 |
|---|---|---|
| `math-model-coach/` | **数模教练**（纪律版）：从读题到成稿的流程与门，含机检脚本 | SKILL 298 行 + 4 篇参考 + 1 个脚本 |
| `math-modeling-skill/` | **案例与知识库**：139 张国赛优秀论文案例卡 + 10 份知识文档 + 模板 + 代码骨架 | 466 行 SKILL + 191 文件 |
| `research-methodology-master/` | **L3 方法论层**：科研通用准则，教练会引用它 | 12 KB |

三者是分工关系，不是三个平行选项：

- 教练管**流程与判据**（该做什么、做到什么程度算过关）
- 案例库管**供给**（同类题怎么解、验证怎么做全、创新怎么筛）
- L3 管**底线**（通用科学准则）

## 二、怎么装

三个目录**必须放在同一级**（比如都放进 WorkBuddy 的 skills 根目录）：

```
<你的 skills 目录>/
├── math-model-coach/
├── math-modeling-skill/
└── research-methodology-master/
```

**为什么必须同级**：教练正文里用相对路径引用案例库，例如 `math-modeling-skill/knowledge/innovation-patterns.md`。如果三者被拆到不同层级，这些引用会失效，教练就查不到创新与验证细则。

装完自检一条命令（在 `<你的 skills 目录>` 下执行）：

```bash
ls math-model-coach/SKILL.md math-modeling-skill/SKILL.md research-methodology-master/SKILL.md
```

三个都在，就装对了。

## 三、机检脚本怎么用

这是包里最实用的部分，纯 Python 标准库，**不需要装任何第三方包**（Python 3.8+ 即可）：

```bash
python3 math-model-coach/scripts/check.py <你的交付包目录>
```

它会检查五件事：

| 规则 | 查什么 | 判定 |
|---|---|---|
| R1 | 假设表标了「未检验」，摘要/结论却直接用它的结果 | FAIL |
| R2 | 摘要超一页、正文超篇幅 | WARN / FAIL |
| R3 | 图片文件缺失、图表编号引用断链、图注缺单位 | FAIL / WARN |
| R4 | 参考文献条目不可解析（疑似编造或占位） | FAIL / WARN |
| R5 | 「题目要求清单」里有没有未做/未用/自拟的项 | FAIL（没写理由）/ WARN（写了理由） |

退出码：`0` 全过、`1` 有 FAIL、`2` 只有 WARN、`3` 目录里没有 md 文件。

**R5 值得特别说明**：它要求你在赛题读完时就产出一张「题目要求清单」（每一问、每一项题给数据、每一项题给公式，各占一行）。缺项可以写理由，但**缺项本身必须显形**——不会因为你写了「时间不足」就当没发生过。

## 四、依赖与兼容

- **Python**：机检脚本只用标准库；案例库里部分代码骨架需要 numpy/pandas/matplotlib，按需安装。
- **frontmatter 字段**：SKILL.md 头部含 `layer`、`upstream_L3` 两个自定义字段，用来标明在技能体系里的层级。如果你的安装器不认这两个字段，删掉这两行不影响任何功能。
- **不依赖联网**：案例卡与知识文档全部本地，检索脚本 `math-modeling-skill/scripts/search_cases.py` 也是纯本地。

## 五、这一版的改动（相对早期版本）

早期版本 772 行，是「教程 + 流程 + 判据」的混合体。这一版做了三件事：

1. **删教程留判据**：算法家族树、代码模板、交互话术、示例场景全部删除——这些模型已经会，留着反而会把探索性工作压成按清单执行。772 → 298 行。
2. **门显性化**：Gate 0（方案锁）/ Gate 1（证据门）/ Gate 2（交付门）写在开头，进技能就看得见。
3. **加了完整性对账**：题目要求清单 + R5 机检。这一条是被真题打出来的——曾出现「三问做了两问、五个效率项实现了三个」却不被任何机制拦住的情况。

已用 2023 A（定日镜场）、2023 B（多波束测线）实跑验证，2023 B 的 Q1–Q3 结果与公开国奖论文逐位吻合。

## 六、已知局限

- R1 抓的是「提到了未检验假设还当结论用」，抓不到「完全不提假设、直接报数」——后者只能靠结论数字挂假设编号的人工习惯。
- 机检只查形式断链，查不到模型建错了。真正防「自洽但错」的是 SKILL 里 F/G 两道人工门。
- 案例库里有部分论文的验证方式标注为「未在证据包中稳定识别」，意思是**原作也没展示验证**。借思路可以，不能当「这样就算验过了」的样本。
